# 🤖 005 — Многоагентная параллельная работа, статус шага и Skills-first

> 📌 Действует для **всех** агентов проекта Octopus Browser (ChatGPT + GitHub-плагин,
> Arena, Claude, Gemini, Codex и др.), работающих **параллельно, с разных машин**.
> Синхронизировано с канонической инструкцией `/root/agents/57_multiagent_parallel_external_skills_research.md`.

---

## 1. 🌐 Параллельная работа с разных машин и агентов

- 🤖 Над этим репозиторием и его деплоем **одновременно** могут работать разные
  ИИ-агенты (Claude, ChatGPT, Gemini, Codex, Arena и др.) с разных машин/окружений.
- 🔍 Перед любой правкой — **всегда** сначала `git fetch` + прочитать последние
  коммиты, открытые PR и `docs/agent-instructions/STATUS.md` (см. п.2).
- 🚫 Запрещено монопольно и молча блокировать общие ресурсы (ветку `main`, сервер,
  секреты) — фиксировать своё намерение в статусе перед началом работы.
- 🤝 Конфликты правок разрешать через аккуратный merge/rebase и `*.bak`-бэкапы,
  не затирая чужой прогресс молча.

---

## 2. 📊 Пошаговый статус работы (обязательно)

- ✅ Перед началом и сразу после каждого шага агент обновляет статус:
  - 🖥️ кто выполняет (агент/модель/машина),
  - 🎯 текущий шаг и цель,
  - 📈 прогресс (сделано / выполняется / следующее),
  - ⚠️ ошибки и результат проверки.
- 📁 Место фиксации в этом проекте: `docs/agent-instructions/STATUS.md` (создаётся
  при первом использовании) + `/root/agents/STEP_STATUS.json` на сервере (общий
  межпроектный статус, см. инструкцию №57).
- 🔄 Цель — чтобы **любой другой агент** в любой момент видел точную картину:
  что уже сделано, что в работе, что дальше.

---

## 3. 🧬 Лог работы → основной Skill агента

- 📚 Лог работы, накопленный опыт, цепочки команд и решения по интеграции **не
  остаются мёртвым текстом** — они кристаллизуются в Skill.
- 🗂️ Skills этого проекта — в каталоге `skills/` репозитория (создать при первом
  использовании), формат: `SKILL.md` + код + тесты + ограничения.
- ♻️ Любая завершённая задача → отчуждаемый, переиспользуемый навык для роя агентов.

---

## 4. 🛠️ Skills-first (обязательно)

- 1️⃣ Найти существующий skill (в `skills/` проекта и в `/mnt/agents/-Octopus/skills/`).
- 2️⃣ Использовать/улучшить его вместо одноразовой реализации.
- 3️⃣ При отсутствии — создать новый skill с документацией и тестом.
- ❌ Запрещено решать повторяющиеся задачи разовыми неструктурированными командами,
  если под них есть или может быть создан skill.

---

## 5. 🔎 Обязательный поиск и deep research перед каждым шагом

- 🌍 **Перед каждым шагом** — проверить наличие готового skill/инструмента в
  открытых источниках: MCP servers, Claude Skills, HuggingFace Hub, LangChain/
  LlamaIndex hubs, GitHub/GitLab по ключевым словам задачи.
- 📖 Провести глубокое исследование: issues/PR по теме, актуальная документация и
  changelog используемых библиотек (FastAPI, Playwright и т.д.), best practices,
  готовые архитектурные паттерны.
- 🧩 Сопоставить найденное с ограничениями инфраструктуры проекта (сервер, лимиты,
  безопасность) — и только затем реализовывать.
- 📝 Кратко фиксировать источники исследования в отчёте/статусе шага.
