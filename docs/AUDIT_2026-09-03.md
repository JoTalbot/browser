# 🐙 Octopus Browser — security & production audit (2026-09-03)

## Executive result

The adapter is suitable for continued development, but production exposure must remain gated behind API authentication, restrictive egress policy, isolated profiles, bounded browser concurrency and deterministic CI.

## 1. API security

- `OCTOPUS_API_KEY` protects operational endpoints.
- Missing configuration returns `503`; an incorrect key returns `401`.
- `/health` remains public for liveness checks.
- Default bind is loopback (`127.0.0.1`).

## 2. SSRF / egress

- Only absolute `http` and `https` URLs are accepted.
- Userinfo in URLs is rejected.
- Optional `ALLOWED_HOSTS` provides an allow-list.
- DNS results are checked and non-global addresses are rejected.
- Remaining production hardening: enforce the resolved destination at the network/browser layer to close DNS-rebinding windows.

## 3. Filesystem isolation

- Profile identifiers are restricted to `[A-Za-z0-9_-]` and 64 characters.
- Profile paths are resolved and verified below the managed root.
- Session identifiers are bounded and resolved below the sessions root.

## 4. Browser runtime

- Playwright default action and navigation timeouts are configured from `NAVIGATION_TIMEOUT_MS`.
- Browser work is bounded by `MAX_BROWSER_CONCURRENCY`.
- Browser shutdown is performed in `finally` blocks.

## 5. Agent behavior

- Empty tasks are rejected.
- Step count has an explicit lower bound.
- Exhausting the step budget produces `limit`, not a false `done` state.
- Browser cleanup occurs even when an action fails.

## 6. Data handling

- Session storage contains cookies/local storage and must be treated as secret material.
- Session export/import is base64 transport, not encryption.
- Never log raw storage state, cookies, API keys or vision credentials.

## 7. CI quality gate

Required checks:

1. Ruff lint.
2. Pytest.
3. Security-focused unit tests.
4. PR status must be green before merge.

## 8. Remaining production risks

- DNS rebinding needs network-layer enforcement, not only preflight DNS checks.
- Persistent Playwright profiles require one-writer-per-profile locking if concurrent requests can target the same profile.
- Session files should eventually support authenticated encryption at rest.
- Rate limiting and request correlation IDs should be added before Internet-facing deployment.
- Browser process/container isolation should be strengthened for untrusted tasks.
